## 1. 目标与非目标

**目标。** 在现有架构（链二：每日引擎 + 面板 + 因子档 + 预测登记 + 纸面组合）之上，做出一个**每天产出持仓名单、名单变化即买卖**的选股框架：每天输出今日持仓、候补名单、临近退出的持仓、**交易清单**（买什么、卖什么、多少股、原因），并在**纸面账本**里按 T+1、整手、涨跌停、停牌和费用真实记账。

**非目标。**
- 不接券商、不下真实订单（`PaperPortfolio` 在运行期禁止联网，见 `backtest/paper.py`）。
- 不宣称这套框架有超额收益。账本的权益曲线只是记录；证据只来自预测层的前向评估（§8）。
- 不改 P6 已登记配置的行为；P6 的策略形态保留，用于读取历史。
- 不做智能体 / LLM（方案 C）、否决层（方案 A）、模型特征（方案 B）；本设计只为它们**留出接口**（§4.1）。
- 不新建第二个引擎（ADR-0005）。

## 3. 证据基础（探索性，不是证据）

上游文档 §3 给出：IC 集中在输家端、剔除输家尾部的毛超额、基准偏小盘、功效不足。本设计新增的验证（2026-10-13，研究期 2017-01..2021-10 共 59 个信号日，20 日持有，对可投资等权，成本取协议口径，**样本内、阈值事后选定**）。**第 1–3 条在全部板块上测得；第 4–5 条在沪深主板 + 创业板上测得**：

1. **每天重抽等于把收益付给成本**：N=100、每期重抽，毛超额 +3.55%、成本 3.60%、净 −0.05%；换手 98%/期。
2. **粘性持仓是收益的另一半**：同样随机入选，只在掉出幸存集合时才换，毛超额升到 +6.4%（N=100）；每期仅换 5–6%。这不是计算假象（每天重抽的对照与"持有全部幸存者" +3.7% 吻合），而是边界附近的股票表现最差、粘性自然远离边界。
3. **按合成分取最高不优**：幸存者里取前 N（每期重选），N=50 净 +0.5%、跟踪误差 13.6%；最高一档十分位也没有 alpha。
4. **≤10 只是高波动彩票**（沪深主板+创业板，粘性随机入选，对种子做 60 次平均，净超额 / 跟踪误差 / 单年超额 p10·中位·p90 / 单年跑输概率）：N=8 +8.3% / 13.6% / −7.3·+8.9·+25.7% / 24%；**N=10 +7.7% / 12.7% / −5.9·+7.7·+22.4% / 24%**；N=15 +6.5% / 11.2% / −4.7·+7.2·+21.0% / 22%；N=30 +6.6% / 9.5% / −3.0·+6.8·+18.7% / 19%。蒙特卡洛噪声约 ±0.7%。
5. **去掉科创板与北交所后信号仍成立**（N=10 净 +7.7%，对比全部板块的 +6.6%，在噪声内）。
6. **确定性取最高 / 居中的结果不可靠**：它们各自只对应样本里的一条路径，N=10 下不同退出规则可差 +15% 对 +4%。**不据此选规则。**
7. **可复现性隐患**：用集合迭代顺序做随机抽样，同一份数据在不同进程里数字不同（`PYTHONHASHSEED`）。正式实现必须**先排序、再用固定种子的哈希选**（§4.3）。

**对期望的诚实表述**：样本内净超额约 +7%，打 30–60% 折扣后约 +3–5%/年（假设）；跟踪误差约 12–13%；N=10 时单年跑输的概率样本内约 25%，打折后约 35–40%。**一年的纸面结果几乎全由运气决定**，一两年的前向记录无法证明或否定这套方法。

## 4. 架构

### 4.1 三层结构（同时是方案 A / B / C 的接入点）

```
 可投资 + 幸存者层（避开）      选择层（可插拔）            持仓策略层（粘性）
 ───────────────────────      ─────────────────         ───────────────────────
 账户可交易板块                 SelectionRule：            已持有 → 只在失去资格或
 流动性前 70%                   (入选候选, 种子) →         掉出幸存集合时卖出
 剔除 ST / 停牌 / 次新          确定性排序                 补仓按选择层顺序
 剔除合成分最差 2 个十分位       默认：种子哈希（占位，      卖出后冷却 20 个交易日
   ▲ 方案 A 的否决层加在这里     不宣称有效）               每日最多 2 笔替换
                                ▲ 方案 C 在幸存者内部评估
                                ▲ 方案 B 的模型分数替换这里
```

### 4.2 每日数据流（收盘后，次日 09:15 前完成）

1. **更新面板**：只取 Step 0 需要的数据集（价格、复权、涨跌停、停牌、日历、登记簿、名称史、指数）；**不取财报**，也不用 walk-forward 模型。
2. **构建因子**：仅四个价格类因子的 `processed` 档（`residual_vol_60`、`return_vol_60`、`turnover_60`、`downside_vol_60`），不再是 21 因子 × 三档。
3. **资格 → 合成分 → 幸存者**。
4. **持仓策略 + 选择层** → 目标持仓（≤ N）。
5. **交易清单**：与纸面账本的当前持仓取差，生成下一交易日开盘的买卖订单。
6. **纸面账本推进**：用 `PaperPortfolio` 按已观察到的真实开盘价推进上一日的订单。
7. **预测登记**：把合成分登记成预测记录（§8），先于次日 09:15。
8. **摘要与日志**：持仓、候补名单、临近退出名单、交易清单、账本权益；幂等，同一日第二次运行不发请求、不写文件。

### 4.3 确定性与可复现

- 选择层默认规则 `seeded_hash/v1`：对入选候选按 `sha256(f"{seed}|{ts_code}")` 升序排序（**与日期无关**，队列稳定），补仓按队列顺序取。种子来自登记配置。
- 所有集合先 `sorted` 再使用；有一条测试用不同的 `PYTHONHASHSEED` 在子进程里运行同一输入，断言输出逐字节相同。
- 交易清单的订单顺序、内容和内容寻址身份都是输入的纯函数。

## 7. 交易清单与纸面账本语义

- **清单列**：`session`（计划执行日）、`side`、`ts_code`、`name`、`quantity`（100 的整数倍）、`reference_price`（信号日收盘）、`reason`（`INITIAL_BUILD / EXIT_SURVIVOR_LOST / EXIT_ELIGIBILITY_LOST / ENTRY_REPLACEMENT / CARRIED`）、`expires`、`status`。
- **数量**：目标金额 = 当日权益 / N；`qty = floor(金额 / 参考价 / 100) × 100`；`qty = 0` 则该候选不可入选，选择层顺延到下一名；现金不足时按可用现金向下取整。
- **执行**：订单在下一交易日开盘价成交（含滑点、费用），受 T+1、涨停买不进、跌停卖不出、停牌的约束，全部沿用 `AShareExecutionPolicy`。
- **未成交**：买单顺延，每次顺延前重新核对资格，不再是幸存者的候选直接取消；超过 3 个交易日取消并重排；卖单持续到成交。
- **首次建仓**：第一日一次性买入 N 只（v1 不做分批；这是一次择时运气，写入报告）。
- **幂等**：同一信号日重复运行得到同一清单、同一账本状态；账本推进按"已观察交易日"，不重复记账。
- **日志**：每日日志含全部输入摘要、资格否决的原因码计数、合成分分位、决定及原因，使任何一笔交易都能追溯。

## 8. 评估与措辞

- **证据层**：预测层。每个交易日登记合成分（可投资范围内全部证券），前向评估十分位价差与 IC；h=20 与 h=5。这是唯一被称为"证据"的东西。
- **记录层**：纸面账本的权益曲线、对账户可交易范围内可投资等权与中证 500 的相对收益。报告里**逐份写明**："N=10 时单年结果主要由运气决定，不是证据"。
- 措辞一律"候选"；不写收益承诺；任何措辞升级都靠前向证据。

## 9. 测试策略（测试先行）

**原则**：先写会失败的行为测试，再写实现；领域内核全部是纯函数，**不需要面板**，可以快速、确定地写满。

**A. 领域单元测试（`tests/unit/domain/`，纯 Python）**
- 资格：表驱动，每个原因码一条（板块、次新、ST、停牌、流动性、缺因子值、买不起一手），并断言原因码优先级与计数。
- 合成分与幸存者：10–20 只的手算夹具（方向取符号、十分位边界、并列处理）。
- 选择规则：稳定（相同输入逐字节相同输出）、与输入顺序无关（打乱输入）、对种子敏感、与日期无关；子进程用不同 `PYTHONHASHSEED` 断言相同。
- 持仓策略：首次建仓；无事发生；掉出幸存者则卖；失去资格强制卖；补仓取队列下一名；冷却期内不重买；每日替换上限；不足 N 个候选时部分建仓；`qty = 0` 的候选被跳过。
- 数量与预算：整手向下取整、现金不足、价格贵到买不起。
- 交易清单：与持仓取差的正确性、原因码、确定性排序、内容寻址身份、JSON 往返。
- **不变量**（固定种子的随机夹具循环）：持仓数 ≤ N；买卖不重叠；卖出 ⊆ 当前持仓；买入不在冷却期；单日替换 ≤ 上限；换手有界。

**B. 适配器与集成测试**
- 用测试时生成的面板夹具：资格否决、合成分与幸存者与手算一致；不得读取信号日之后的数据（前视守卫）。
- **纸面账本**：手算的 3–4 个交易日夹具——开盘成交、涨停买单顺延、跌停卖单顺延、3 日后取消、费用与整手、T+1。
- **每日流程**离线端到端：同一日运行两次，第二次零请求、零写入；跨年；缺数据的拒绝都是具名的。

**C. 变异检查**：对策略函数的关键分支（去掉冷却、反转比较、去掉替换上限、取最高而非队列）逐个变异，断言至少一条测试变红；变异清单进报告。

**D. 台账与守卫**：新能力加台账行，`acceptance_test` 绑定真实 node id；不引入被跳过的测试；本机 + 跨平台差异（`libm`、路径、编码）按 P6 的教训预先避免（夹具不用超越函数）。
