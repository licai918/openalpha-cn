# OpenAlpha CN 如何形成竞争优势

## 结论

OpenAlpha CN 不以“Agent 数量更多”作为主要卖点，而以 **A 股数据语义、Point-in-Time 正确性、可复现决策和验证闭环** 建立壁垒。

2026-07-24 的源码级审计锁定：

- TradingAgents：`a33fd4c0f134485a43553a2c23a63cb14adbd88f`，Apache-2.0；
- AI Hedge Fund：`e7c784f118866c5dba8fc2c4ee545f08cc611c61`，MIT；
- 共识别 257 项上游功能，原规划真实覆盖 132 项（51.36%），未审计和未知均为 0。

OpenAlpha CN v1 没有复制两个仓库，而是优先实现审计中最影响可信度的缺口：统一 PIT 合同、内容寻址证据、显式失败/弃权、确定性 `run_cycle`、版本化 Run Manifest、有界重试、A 股执行约束和结果归因。

## 六个胜负手

| 维度 | OpenAlpha CN 的做法 | 用户价值 |
|---|---|---|
| 数据时间 | 同时记录事件、可得、入库、修订时间 | 历史研究不会偷看后来才知道的信息 |
| A 股语义 | 涨停、炸板、连板、题材、催化、公告、资金 | 不需要把海外通用因子硬翻译成 A 股 |
| 证据链 | 每项证据有来源、许可、哈希和稳定 ID | 任何结论都能回到原始事实 |
| 研究运行 | 无 LLM 也可确定性运行；模型输出强制 Schema | 降低模型漂移、解析失败和演示式功能 |
| 回放执行 | 实时/回放同核心，加入 T+1、整手、停牌、涨跌停锁单 | 回测路径更接近 A 股现实 |
| 验证改进 | 决策、未来观察、基准、成本、规则/因子/Agent 归因对账 | 知道结果来自哪里，而不是只看一条收益曲线 |

## 数据优势不是公开转售数据

项目的公开价值是 **数据协议和接入能力**：

1. 用户导入自己有权使用的数据；
2. Provider 声明凭据、缓存、时效、限流、失败和再分发政策；
3. 统一构建不可变 Evidence Snapshot；
4. PIT 查询只返回决策时刻已经可知的版本；
5. API、SDK、CLI、Web 与回放使用同一证据对象。

这允许社区为不同合法数据源开发 Adapter，同时避免仓库承担商业数据再分发风险。

## 不靠“大范围铺功能”制造幻觉

具备大范围扩展条件之前，必须先有：

- 稳定、版本化的 Provider / Agent / Tool / Risk / Validator 合同；
- 明确的输入输出 Schema 与错误语义；
- 可重复的冻结 Fixture；
- 统一的运行清单、随机种子和配置摘要；
- 防前视与同路径回放；
- 每项功能的源码、入口、测试和文档证据；
- `UNREVIEWED=0`、`UNKNOWN=0` 的去向台账。

v1 已建立这些地基。后续可并行扩展事件族、Provider、Agent 和研究方法，而不会把同一逻辑复制进多个界面或回测分支。

## 真实边界

- v1 不做券商实盘连接；
- 不宣称 300 个合成事件证明策略盈利；
- 不把 AI Hedge Fund v2 或 Web Flow Builder 的 WIP 愿景算作稳定能力；
- 不把 TradingAgents/AI Hedge Fund 源码复制进本仓库；
- 不公开链邻数据库、用户知识库、Token 或商业原始数据；
- 组合现金/持仓逐日核算和图形化 Agent 编排明确延后。

完整状态见[功能去向台账](release/openalpha-v1-feature-ledger.md)。
