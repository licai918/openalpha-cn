## 1. 起点：P6 交付了什么，没有回答什么

**P6 交付**（见 `p6-results.md`）：多年全市场点时间面板、因子三档、预登记的三阶段研究、一次性保留期、每日一条命令、前向周报。R1–R7 成立，CI 七绿，已合并进 `main`。

**P6 的研究结论是负面的**：登记的配置（walk-forward 梯度提升打分、持仓 50、每 20 个交易日调仓、行业上限 20%）在保留期（2024-01-02..2026-09-24）三条判据全部不满足——复合年化相对收益 −0.0400（须 > 0）、单侧 p 0.7287（须 < 0.05）、最大相对回撤 0.1933（须 ≤ 0.1240）。阶段 2 无配置通过多重检验。研究期 IR 0.332、验证期 0.595、保留期 −0.375，三者在统计上都与 0 无法区分（研究期 IR 的标准误约 ±0.45，推算）。

**P6 没有回答的两个问题**：

1. **因子之外的决策层有没有增量？** 智能体、证据、委员会从未被当作一套选股策略检验过。P6 检验的只是因子打分这一层。
2. **"前 50 只等权"是不是用好信号的方式？** 诊断（§3）显示不是：账本里显著的 IC 集中在输家一端，集中做多的形态几乎收割不到。

**保留期窗口已经用过一次。** 2024-01-02..2026-09-24 的数据对登记的那一个配置是一次性保留；之后任何**在看过它之后**设计的策略，在这段窗口上的结果都不再是确认性证据（§7）。新的确认性证据只能来自**前向样本**。

## 2. 当前架构事实（2026-10-08，`1d7b4a3`）

标签：**[运行]** 代码存在且出厂 CLI/REST 路径可达或被端到端测试驱动；**[仅库]** 代码和测试都有，但出厂路径不构造它，只有 Python 调用方能用；**[声称]** 只在文档、ADR、docstring 或合同里声称，没有出厂调用方。`文件:行号` 以本基线为准。

### 2.1 两条决策链

| | 链一：研究决策链 | 链二：每日选股链（P6） |
|---|---|---|
| 入口 | `shortlist run` → `run_cycle`（逐只）→ 可选 `deliberate` → `portfolio construct` | `scripts/daily_selection.py` |
| 打分 | 因子档加权和（`cross_section._score`） | 登记配置的打分源（walk-forward GBM / 滚动 IC / 静态）（`strategy_backtest._ranked`） |
| 智能体 | 规则型基线；LLM 智能体只能由 Python 调用方接入 | 不使用 |
| 是否被检验 | 没有作为一套选股策略检验过 | 保留期检验：**不通过** |
| 是否预登记 | 否 | 是（`aebaac5`） |

### 2.2 链一不是一条自动链（与此前的口头描述不同，已更正）

- **[运行]** `shortlist run` 只读面板，不调用 `run_cycle`（`src/openalpha_cn/shortlist_view.py:518`，code `the_evidence_plane_is_supplied_rather_than_run_by_this_module`）。`run_cycle` 要逐只另行执行，再把 `{signal, run_manifest_id}` 手工拼成 `--evidence` JSON 喂回。
- **[运行]** `run_cycle` 默认零面板读取、零 LLM：证据由请求体带入，默认 roster 是三个规则型基线（`runtime/engine.py:71`）。出厂 CLI、REST、批量都不传 `agents` / `features`。
- **[运行]** 智能体的结论**不改变排序、入选和权重**：`portfolio construct` 只读 `subject / rank / score`（`backtest/portfolio_policy.py:508-530`）。链一的终产物是 `final_action ∈ {watch, avoid, abstain}` 加聚合 `SignalFrame`（方向、强度 ∈ [−1,1]、置信度，`horizon` 恒为 `"5d"`），**没有仓位**。
- **[声称]** 涨停 / 炸板 / 连板 / 题材 / 公告 / 资金证据：规范化器和规则型智能体存在，但出厂生产者只有 `FileProvider`（用户自备文件）。链邻和 AKShare 只被 `doctor` 构造（`cli.py:647-668`）；Tushare 数据集表里没有这些事件类数据；面板里只有原料（`daily` + `stk_limit`），没有炸板 / 连板计算。
- **[仅库]** `FeatureScoreAgent`（`agents/feature.py`）只读调用方组合进来的 `FeaturePlane`，出厂路径无法组合；`StructuredSignalAgent`（`agents/model.py`）在 `src/` 和 `scripts/` 内无人构造。
- **[运行]** 默认路径不调用任何 LLM，并有 AST 级前提测试（`tests/integration/test_usage_claims_match_the_shipped_paths.py`）。

### 2.3 链一的智能体规则是人工设定的，未经任何检验

- `MarketAgent`：`limit_up 0.65`、`consecutive_board 0.85`、`broken_board −0.65`，方向阈值 ±0.15（`agents/baseline.py:117-152`）；`CapitalAgent` 按净流入符号取 ±0.4，置信度固定 0.6；`ThemeAgent` 缺省 `score` 取 0.6。
- 不带 `score` 的公告 / 催化证据，强度 0.2 > 0.15，默认读成看多（读代码推得）。
- 聚合是算术平均，弃权按 0 计入；`horizon` 写死 `"5d"`，不管 ThemeAgent 声明的 10d（`engine.py:407-475`）。

### 2.4 LLM 接入点

- `StructuredSignalAgent` 的系统提示只有 117 个字符；发给模型的用户消息只含 `evidence_id / kind / summary`，**不含 facts，也不含特征面板**；提示词没有版本化（`prompt_versions=()`，`engine.py:136`）。
- 仓库唯一的 Provider 是 `OpenAICompatibleProvider`（`models/openai_compatible.py`）：`base_url`、模型名、`api_key_env` 在构造时给定；请求里没有 `max_tokens`；用量只有构造时传了 `usage_store` 才入账。
- 校验失败重试最多 2 次，传输重试最多 3 次。

### 2.5 预测登记容器（链二的前向通道）能承载智能体信号

- `PredictionRecord` 包 `PredictionBatch`：每个证券恰好一个有限的 `score` 或一个 `abstention`；store 自己盖托管时钟，回填无法伪装成 `forward`。
- `AlphaModelDeclaration.family` 是自由字符串；P6 对静态 / 滚动 IC 源已用 `family="strategy_<kind>"` 登记过"没有东西被拟合"的记录（`strategy_registration.py:219-245`）。智能体信号可以走同一个先例。
- 链一自己的回放 / 验证 / 事件研究通道都是逐事件、要手工提供 outcome 的，**不适用于全市场每日选股**。

### 2.6 两条链共享与重复的东西

- 共享：`AShareExecutionPolicy`、`position_quantity`、涨跌停字段函数、`security_board`、因子档存储（两条链读同一套已存分区）。
- 各自一份：打分函数、方向取向、`MarketBar` 组装。`daily_selection.py` 自己写明两个命令实现的不是同一个策略，所以不用 `shortlist run` / `portfolio construct`。
- 链二的 `score_day` 拒绝 `prediction` 源（`strategy_view.py:2280-2284`）。

### 2.7 成本

- 链一无 LLM：纯 CPU，50 只 / 日约 0.4–0.8 秒，200 只 / 日约 1.6–3 秒（读代码**推算**；仓库自测 66–124 items/s）。
- 链一有 LLM：每个 LLM 智能体每只典型 1 次 HTTP，最多 6 次；约 1.5–2k token / 只（**推算**，上界由喂入证据决定）；200 只 / 日约 0.3–0.4M token（**推算**）。
- **链二才是日常的算力大户（实测）**：2026-10-08 每日命令 07:20–08:36（约 76 分钟），首份周报 08:58–10:05（约 67 分钟）。其中拟合与逐条重算的占比待 `V2-P7-007` 先 profile 再定；周报要重算每条已登记预测，随登记天数增长。

**结论**：运行时的算力浪费不在"两条链重复"，因为链一每天根本不跑。真正的整合缺口是**决策缺口**——智能体层没有生产环境的输入通道，也没有接到持仓的输出通道。

## 3. 探索性发现（不是证据）

> **使用边界。** 以下数字来自一次**事后、未预登记**的探索：只读研究期（信号日 2017-01-03..2021-10-29，每 20 个交易日一个，共 59 个），未读取验证期和保留期；我（执行者）看过约 10 个因子才挑出这几个，其中四个高度相关。它们**用来决定下一步测什么**，不能作为任何收益声称的依据。要变成证据，必须经 `V2-P7-006` 预登记并在未用过的数据上重做。

### 3.1 口径

- 因子值取已存 `processed` 档并按因子方向取符号（`lower_is_better` 取负），前向收益为"信号日次日收盘买入、持有 20 个交易日"的复权收盘收益（`adj_factor` 是除权事件的稀疏序列，按 as-of 连接）。
- 合成分 = 四个波动 / 流动性因子（`residual_vol_60`、`return_vol_60`、`turnover_60`、`downside_vol_60`）方向调整后取均值。
- 可投资范围 = 信号日前 20 个交易日平均成交额排在前 70% 的证券；基准为其等权。
- 脚本当前只在对话的临时目录里，**未入库**；工具化（带夹具和研究窗口护栏）是 `V2-P7-004`。

### 3.2 IC 是真的，但落差很大（账本 + 诊断）

- r3 阶段 1 的 IC 次家族有 148 个配置被 BY 拒绝；h=20、processed 档的 IC：`residual_vol_60` +0.089、`return_vol_60` +0.088、`turnover_60` +0.082、`downside_vol_60` +0.057、`book_to_price` +0.046、`reversal_5_sessions` +0.046；`momentum_20 / 60` 约 −0.055。
- 但**同样这些因子的前 50 只组合，扣成本后对全 A 等权持有基准全是负的**：`residual_vol_60` −9.3%/年、`return_vol_60` −7.9%、`turnover_60` −6.6%、`momentum_60` −16.1%。
- 我的诊断复现了 IC 的量级：四因子 IC 约 +0.086 到 +0.099（t 约 5，日期间 IC 标准差约 0.14，76% 的日期为正）。

### 3.3 IC 集中在输家一端

十分位平均 20 日收益减去全体等权（%，从方向调整后"最好"到"最差"）：

| 因子 | 最好 → 最差各十分位 | 前 50 只 | 最差 50 只 |
|---|---|---|---|
| `residual_vol_60` | +0.11 +0.35 +0.45 +0.34 +0.38 +0.27 +0.12 −0.08 −0.42 **−1.51** | −0.09% | −3.25% |
| `return_vol_60` | +0.07 +0.41 +0.37 +0.40 +0.37 +0.23 +0.15 −0.13 −0.36 **−1.51** | −0.25% | −3.11% |
| `turnover_60` | +0.42 +0.38 +0.48 +0.33 +0.24 +0.22 +0.21 −0.14 −0.51 **−1.63** | +0.31% | −3.01% |
| `downside_vol_60` | +0.21 +0.35 +0.31 +0.30 +0.29 +0.28 +0.17 −0.27 −0.42 **−1.21** | −0.24% | −2.42% |

最差十分位平均每 20 天落后约 1.2–1.6%（约 −15% 到 −19%/年），最好一端只是追平甚至略低于最优的中间档；前 50 只还偏大盘（规模分位约 0.75–0.85）。**这些因子的信号是"避开彩票股"，不是"挑出最强的"。**（`amihud_60` 的 IC 在诊断里仅 +0.006，与账本的 +0.052 不一致，原因未查，不用于结论。）

### 3.4 在可投资范围里剔除输家尾部（毛超额，未扣成本，20 日持有）

| 做法 | 毛超额（相对可投资等权） | t | 跟踪误差口径的 IR（样本内） |
|---|---|---|---|
| 剔除合成分最差 1 个十分位 | +2.39%/年 | 3.9 | 约 1.8 |
| 剔除最差 2 个十分位 | +3.71%/年 | 3.7 | 约 1.7 |
| 剔除最差 3 个十分位 | +4.52%/年 | 3.3 | 约 1.5 |
| 可投资范围内合成分前 300 | +4.69%/年 | 1.1 | 约 0.5 |

宽组合剔除尾部的统计量远好于集中做多前 300，因为跟踪误差小得多。**这是样本内、事后挑选的结果**（§3 开头），预估时按 30–60% 打折（**假设**），再扣约 0.3%/年的成本（**推算**：换手低、单边成本约 0.15%）。

### 3.5 基准与"零信号截距"

- 账本里把扣成本超额对 IC 和换手做回归，**零 IC、零换手的截距在三个调仓期都约 −5%/年**（h=20：−5.2%，h=5：−4.8%，h=1：−5.5%）。换成并列报告的中证 500 后，截距约为 0（h=20：+0.6%，h=5：0.0%）。（对中证 500 的数是按逐行比例换算的**粗略代理**，不是重新测量。）
- 直接比较：全 A 等权减可投资等权，在 2017–2021 的样本内平均 **+1.7%/年**（逐年 −1.0、+4.3、+1.3、−0.5、+5.2）。
- 因此 −5% 的"拖累"大部分是**基准偏重小盘的口径问题**（至少约 1.7%，其余未解释），不是引擎缺陷，也不是"信号反了"。**空信号对照（`V2-P7-002`）才能把它量干净**，在那之前不改任何基准口径。

### 3.6 统计功效决定该测什么（**推算**，日期间 IC 标准差按实测 0.14）

| 要检出的量 | 需要的非重叠 20 日期数 | 约合 |
|---|---|---|
| IC 0.10（t=2.4） | 12 | 1 年 |
| IC 0.05（t=2） | 32 | 2.6 年 |
| IC 0.02（t=2） | 200 | 16 年 |
| 组合超额 IR 0.5（t=2） | — | 16 年 |
| 组合超额 IR 1.0（t=2） | — | 4 年 |

结论：**组合收益这一层几乎无法在几年内确认**，评估必须放在**预测层**（IC、十分位价差）和更短的持有期（h=1、h=5，独立样本多得多）。智能体层的增量 IC 如果小于 0.03，在 h=20 上根本测不出来。

### 3.7 补充（2026-10-13）：小账户与持仓粘性

在 §3.1 同样的口径上，为 35 万资金、≤10 只做的补充验证，结果和阈值的事后性质同上：每天重抽 100 只净 −0.05%（换手 98%/期），同样随机入选但只在掉出幸存集合时才换，毛超额从 +3.6% 升到 +6.4%（换手 5–6%/期）；按合成分取最高并每期重选，N=50 净仅 +0.5%；≤10 只的跟踪误差约 12–13%/年，单年超额 p10 ≈ −6%、p90 ≈ +22%；去掉科创板与北交所后信号仍成立。完整表格与解读见 Step 0 设计文档 §3。**结论：这套信号的价值在"避开"和"惰性"，不在"挑强势股"；换股会很稀疏，N=10 约两个月一次买卖。**

### 3.8 这些发现能用来做什么、不能做什么

- **能**：决定 Step 0 的候选形态（宽组合剔除尾部）、决定要预登记的基准、决定功效不足时放弃哪些评估口径。
- **不能**：声称任何收益；证明智能体层有无增量（它没有被测过）；替代预登记。

## 4. 方案与取舍

用户的评估框架：**Step 0 与方案 C 并行 → 视结果做方案 A → 之后再做方案 B**。下面的预估都带假设，路线图修订时必须一并检查这些假设。

### 4.0 现状基线：walk-forward 模型不作为整合的基础

登记的模型没有可靠证据（研究 IR 0.33、验证 0.60、保留期 −0.38，统计上与 0 无异）。整合方案都不以它为前提；它只在 Step 0 里作为"打分源之一"被预登记比较。

### 4.1 Step 0：持仓形态改造（不依赖智能体）

- **做什么**：把"前 50 只等权"改成"可投资范围里剔除输家尾部的宽组合"；预登记**可投资等权**和**中证 500**为并列基准；先做空信号对照量出真实拖累；修算力。
- **预估**：对可投资等权的净超额约 **+1% 到 +2.5%/年**，跟踪误差约 2–3%。依据：§3.4 的 +2.4–4.5% 毛超额打 30–60% 折扣后，再扣成本。**这是防御性倾斜，不是高 alpha 选股。**
- **可测性**：预测层很好（IC / 十分位）；组合层很差（§3.6）。
- **算力**：与现状同量级，另有拟合缓存可降到每日约 15 分钟以内（目标，待 profile）。
- **主要风险**：事后挑选、样本内；因子拥挤导致衰减；剔除尾部的收益集中在 2018 / 2021 两个年份（逐年待核实）。

### 4.2 方案 C：智能体作为前向登记信号，设增量门槛

- **做什么**：每天对候选前 300 名跑 `run_cycle`（规则型 + DeepSeek），把方向 × 强度映射成每证券一个 `score`（弃权 → `abstention`），以 `family="agent_*"` 登记成 `PredictionBatch`，standing=`forward`。**不交易、不改持仓**。评估：智能体分数相对因子分数的增量 / 偏 IC，h=1 与 h=5。
- **预估**：净超额 0（不交易）。产出是"智能体层有没有增量"这个结论本身。
- **可测性**（**推算**）：按每日非重叠样本、日 IC 标准差 0.10（**假设**，待 `V2-P7-004` 实测）：120 个前向交易日在 h=1 上可检出增量 IC ≈ 0.02（t≈2）；h=5 仅 24 个非重叠期，按 h=20 实测的日期间标准差 0.14 沿用，只能检出 ≈ 0.06。
- **算力**：约 0.6M token / 日（300 只，**推算**）。
- **主要阻碍**：智能体没有证据输入通道（§2.2）——需要先有证据生产者（V2-P7-010 核实事件数据、V2-P7-011 从面板推导涨停 / 炸板 / 连板）。
- **主要风险**：LLM 的历史回测会被训练数据污染——所以**只做前向**，历史回放中拒绝 LLM 智能体（V2-P7-015）。

### 4.3 方案 A：单引擎 + 智能体否决层（待 C 的闸门）

- **做什么**：Step 0 的宽组合为主引擎，智能体只对持仓名单做否决 / 降权（规则型先行，LLM 后行）。
- **预估**：Step 0 的 +1–2.5%，否决层的增量先按 0 计，范围 −0.5% 到 +1.0%（**假设**，无依据，需要 C 的结果）。
- **工程**：在资格层新增一个来自智能体的否决原因码，并给 `survivor-book-config` 加一个版本字段 = 新配置版本 + 重新登记，**不需要迁移**（T4 §7）。**开闸前必须先决定**：否决一只**持仓**是"只阻止入选"还是"强制卖出"——后者走强制退出，不受每日替换上限约束，会带来高频进出（T4）；A 开闸时再切 issue。

### 4.4 方案 B：证据变特征，并入同一个 walk-forward 模型（最后做）

- **做什么**：涨停 / 炸板 / 连板等从 `daily` + `stk_limit` 推算成点时特征（`limit_touch` 已在 `domain/price_limits.py:1102-1129`）；资金流、题材、公告若新增数据集再并入；与因子一起进模型，用同一套预登记协议检验。
- **预估**：0 到 +3%，**不确定**。只有配合 Step 0 的形态改造才有意义，因为问题在"怎么用信号"而不在"信号不够多"。
- **主要风险**：特征变多更易过拟合；涨停名买不进；新数据集需要回填（约 3–6 千次请求 / 数据集，**估算**，须先取得用户同意）。

### 4.5 预估汇总

|---|---|---|---|---|
| 净超额（对可投资等权） | +1–2.5%/年（假设） | 0 | Step 0 + (−0.5…+1.0)% | 0…+3%（不确定） |
| 评估层 | 预测层 | 预测层（增量 IC） | 预测层 | 预测层 |

### 7.2 保留期与窗口

- 2024-01-02..2026-09-24 已用于登记配置的一次性保留期。P7 把它标为"**二次使用、非确认性**"：可以作为额外验证，但结论措辞必须注明。

### 7.3 LLM 的特有问题

- 历史回测污染：模型训练时可能见过评估期之后的新闻和走势。**LLM 派生信号只允许前向使用**；历史回放 / 回测中遇到 LLM 智能体按名拒绝（`V2-P7-015`）。
- 规则型智能体的权重（§2.3）是人工设定，不得因为"测试通过"被当作已验证；它们进入前向评估时与 LLM 智能体同等对待。

### 7.4 措辞

结论一律用"候选"。不写收益承诺；不把探索性数字写成发现的"效应"。
